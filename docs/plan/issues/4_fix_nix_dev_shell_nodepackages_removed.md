# GitHub Issue #4: fix(nix): dev shell fails to evaluate — nodePackages removed from nixpkgs-unstable

**Issue:** [#4](https://github.com/denhamparry/template/issues/4)
**Status:** Planning
**Date:** 2026-07-02

## Problem Statement

Entering the nix dev shell (`nix develop` or `direnv allow`) fails to
evaluate:

```text
error: nodePackages has been removed. Many packages are now available at the
top level (e.g. `pkgs.package-name`). Check on https://search.nixos.org to
see if the package is still available.
```

### Current Behavior

- `flake.nix` tracks `nixpkgs-unstable` (`flake.nix:5`) and references
  `pkgs.nodePackages.prettier` (`flake.nix:30`).
- A freshly generated `flake.lock` pins nixpkgs revision `e8273b2`
  (2026-07-01), where the `nodePackages` attribute set has been removed.
- Anyone creating a new project from this template gets a broken dev shell
  immediately — the flake fails to evaluate, so `nix develop`, `direnv
  allow`, and the advisory `nix.yml` CI workflow all fail.
- Repos with an older committed `flake.lock` are unaffected until they
  update.

### Expected Behavior

- `nix develop` evaluates and enters the dev shell with all tools available,
  including `prettier`.
- `nix flake check` passes against current `nixpkgs-unstable`.

## Current State Analysis

### Relevant Code/Config

- `flake.nix:30` — `pkgs.nodePackages.prettier` is the only reference to the
  removed `nodePackages` attribute set in the repository (verified with
  `rg -n "nodePackages"`).
- All other packages in the dev shell (`pre-commit`, `nodejs`,
  `markdownlint-cli`, `shellcheck`, `gitleaks`, `gh`) already use top-level
  attributes and are unaffected.
- `flake.lock` is **not** tracked in git. The issue #2 plan
  (`docs/plan/issues/2_align_template_with_fleet_conventions.md:244`)
  records the deliberate decision: "No `flake.lock` committed — first
  `nix develop` generates it per-project."

### Related Context

- Upstream nixpkgs removed the `nodePackages` scope; `prettier` is now a
  top-level attribute (`pkgs.prettier`), confirmed on
  <https://search.nixos.org>.
- The `~/.claude` config repo has the same `flake.nix` pattern and needs the
  same fix — out of scope for this PR (separate repository), tracked as a
  follow-up note.
- The `main` worktree currently has a staged, uncommitted `flake.lock` (the
  bug reproduction artifact). Per the issue #2 decision above, it should not
  be committed; it is left for the user to discard.

## Solution Design

### Approach

Replace the removed `nodePackages.prettier` reference with the top-level
`prettier` attribute. This is the upstream-recommended migration (the error
message itself points to top-level packages) and the minimal change that
restores evaluation.

### Implementation

```diff
-            pkgs.nodePackages.prettier
+            pkgs.prettier
```

### Benefits

- Dev shell evaluates again on current `nixpkgs-unstable`.
- New projects created from the template work out of the box.
- No behaviour change: the same prettier CLI lands on `PATH`.

## Notes

### Key Insights

- The template intentionally ships no `flake.lock`, so template consumers
  always evaluate against latest `nixpkgs-unstable`. That makes the template
  sensitive to upstream attribute removals like this one — the trade-off was
  accepted in issue #2 for per-project freshness.
- The staged-but-uncommitted `flake.lock` on the `main` worktree is a
  reproduction artifact and should be discarded, not committed.

### Alternative Approaches Considered

1. **Commit a pinned `flake.lock`** — Would shield consumers from upstream
   breakage but reverses the issue #2 decision and goes stale in a template
   context. Not chosen ❌
2. **Pin nixpkgs to a release branch (e.g. `nixos-25.11`)** — More stable,
   but the fleet convention is `nixpkgs-unstable` and this widens the change
   beyond the bug. Not chosen ❌
3. **Replace `nodePackages.prettier` with top-level `prettier`** — Minimal,
   upstream-recommended migration. Chosen ✅

### Best Practices

- When nixpkgs removes an attribute scope, prefer the top-level attribute
  the error message points to and verify on <https://search.nixos.org>.
- The advisory `nix.yml` workflow runs on flake-file PRs, so CI gives a
  second verification of this change.
